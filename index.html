00 / BEFORE YOU START

From your checkout
to your Blender host.

Set up an owned Windows desktop, declare a Scenario, and return an Evidence Bundle to your developer machine.

Run the shell commands below from a macOS or Linux checkout. Replace the example target values with your own settings.

  • ↗
    A developer machineGo 1.23 or later, Git, and SSH.
  • ↗
    An owned Windows desktopOpenSSH, a safe SSH config alias, and an interactive user logged in.
  • ↗

HOST BOUNDARY

Blender Box does not install Blender or the daemon, or change your SSH, Tailscale, or firewall settings. The Blender MCP add-on stays on Windows loopback.

  1. 01

    Build from source.

    Clone the repository. Build the Windows binary that setup publishes to your host.

    SHELLDeveloper machine
    git clone https://github.com/BramVR/blender-box.git
cd blender-box
GOOS=windows GOARCH=amd64 go build \
	-o /tmp/blender-box.exe ./cmd/blender-box

    The commands in this guide use go run ./cmd/blender-box from this checkout.

  2. 02

    Define your host.

    Create target.json in the checkout. The SSH alias selects a host from your existing SSH config.

    target.jsonHost profile
    {
	"schema_version": 1,
	"ssh_alias": "owned-windows-host",
	"ssh_user": "HOST\\operator",
	"work_root": "C:\\BlenderBox",
	"interactive_user": "HOST\\operator",
	"task_name": "BlenderBoxHost",
	"blender_executable": "C:\\Program Files\\Blender Foundation\\Blender\\blender.exe",
	"session_broker_executable": "C:\\BlenderBox\\bin\\blendersessiond.exe",
	"host_executable": "C:\\BlenderBox\\bin\\blender-box.exe"
}

    Keep credentials, hostnames, IP addresses, and private network details out of the profile. These are example values, not a discovered host.

    Use an ASCII drive path without spaces for work_root. Put both host executables in a dedicated directory below that root. Blender can live elsewhere.

  3. 03

    Set up Windows.

    Preview the setup plan first. Without --apply, setup validates the profile locally and makes no SSH connection.

    SHELLPreview · local only
    go run ./cmd/blender-box windows setup \
	--target target.json \
	--host-binary /tmp/blender-box.exe \
	--json
    Apply setup to your verified hostWrites to Windows

    Run this after you have verified the target is your owned host. Setup publishes the hashed binary, applies managed-path ACLs, checks the daemon contract, and registers the fixed interactive Scheduled Task.

    go run ./cmd/blender-box windows setup \
	--target target.json \
	--host-binary /tmp/blender-box.exe \
	--apply \
	--json

    After setup, check the installed host. This read-only check does not launch Blender.

    SHELLRead-only host check
    go run ./cmd/blender-box windows check \
	--target target.json --json

    A failed requirement returns status: "fail". Fix the reported identity, path, task, or capability issue before you run a Scenario.

  4. 04

    Declare the payload.

    Create payload.json next to your scenario.py. List each file to stage and choose the captures you need.

    payload.jsonSchema 2
    {
	"schema_version": 2,
	"files": [
		{
			"source": "scenario.py",
			"destination": "scenario.py"
		}
	],
	"scenario": {
		"script": "scenario.py",
		"read_timeout_seconds": 600,
		"capture_viewport": true,
		"capture_blender_window": true,
		"capture_desktop": false
	}
}

    Source paths are relative to the payload document. Destination paths are relative to the remote payload root.

    scenario.pyMinimal cube example

    This script adds a cube to the fresh Run's Blender scene, checks its vertex count, and prints the Scenario Result.

    import json
import bpy

bpy.ops.mesh.primitive_cube_add(size=2, location=(0, 0, 0))
cube = bpy.context.active_object
cube.name = "ProofCube"
assert len(cube.data.vertices) == 8

print(json.dumps({
	"schema_version": 1,
	"status": "pass",
	"object": cube.name,
	"vertices": len(cube.data.vertices),
}))
    SCENARIO CONTRACT

    Print exactly one JSON document with schema_version: 1 and status: "pass". Extra stdout makes the result invalid. Returning a dictionary from a function alone does not produce a Scenario Result. Read the Run contract ↗

    Validate the plan locally, then use doctor to check the installed host and requested capture capabilities.

    SHELLPlan, then diagnose
    go run ./cmd/blender-box plan \
	--target target.json --payload payload.json --json

go run ./cmd/blender-box doctor \
	--target target.json --payload payload.json --json

    plan does not contact the host. doctor is read-only. Schema 2 payloads require a matching upgraded host binary.

  5. 05

    Run the Scenario.

    Start a Run with a bounded timeout. The client stages the payload, starts Blender through the fixed Scheduled Task, and returns verified evidence.

    SHELLLaunches Blender on your host
    go run ./cmd/blender-box run \
	--target target.json \
	--payload payload.json \
	--timeout 20m \
	--json

    Save the RUN_ID=bbx_... line written to stderr before validation. With --json, stdout contains one versioned success or failure result.

    LockStageLaunchVerifyClean up

    The client fetches and verifies evidence before stopping its exact Session and removing the remote Run files.

  6. 06

    Recover or stop.

    If your client disconnects, read the durable host receipt with the Run ID. Replace bbx_... with the ID you saved.

    SHELLRead the Run state
    go run ./cmd/blender-box status \
	--target target.json --run bbx_... --json

    To stop that Run, use the same ID.

    SHELLStop the owned Session
    go run ./cmd/blender-box stop \
	--target target.json --run bbx_... --json

    stop recovers the recorded request and Session identities. A process name, port, executable path, or guessed PID is never stop authority.

07 / THE EVIDENCE BUNDLE

A result you
can inspect.

Each Run reserves a new local directory before it contacts the host. Evidence records what ran, what came back, and whether cleanup completed.

artifacts/blender-box/<run-id>/

Use --evidence-dir to choose another new directory. Existing evidence files are never replaced.

SUCCESSFUL RUNWHAT EACH FILE TELLS YOU

manifest.json
Paths, types, sizes, SHA-256 hashes, and capture provenance.
evidence.json
Run and Session identities, deadline, terminal state, and cleanup result.
result/scenario-result.json
The versioned Scenario Result.
screenshots/viewport.png
Scene pixels. Included when requested.
screenshots/blender-window.png
The Blender window with UI chrome. Included when requested.
screenshots/desktop.png
The Windows virtual desktop. Explicit opt-in only.
↗

Choose the evidence that proves your work. A viewport capture shows scene pixels. A window capture shows Blender's UI. A desktop capture can include private information from other applications. Review desktop images before sharing.

KEEP AT HAND

One command.
One clear job.

Use --json for machine-readable output.

windows setup
Local setup plan. --apply publishes to the verified Windows host.
windows check
Read-only inspection of the installed host.
plan
Local target and payload validation.
doctor
Read-only host and capture-capability diagnosis.
run
Execute a Scenario and return verified evidence.
status
Read a durable Run receipt after a disconnect.
stop
Stop the exact Session recorded for a Run.
